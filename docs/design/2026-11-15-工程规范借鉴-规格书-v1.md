# 工程规范借鉴（DSH-Bot 经验）· 规格书 v1

- 日期：2026-11-15
- 状态：待 zhu 确认
- 适用：`dsh-bot-team-tab`（当前 0.4.1）
- 来源：MJ-CJM/DSH-Bot v0.6.7（MIT）的工程实践，v0.6.7 源码已本地审阅

## 1. 背景

审阅 DSH-Bot 后确认，它值得借鉴的不是功能，而是**工程纪律**：202 个测试文件 / 1129 用例 / 6648 断言、1725 行 DSH API 核实记录、每版发布文档带 SHA-256 与「已知限制」、CI 里 build→test→typecheck→lint→死链检查的完整 check 链。

本插件现状：`scripts/selftest.mjs` 217 行手写断言共 16 条，无 check 链，无发布文档，无版本 CHANGELOG；DSH API 的踩坑结论只存在于会话记录里，未落文档。

**硬约束**：本插件靠 `pnpm add github:mufeng-git/dsh-bot-team-tab#tag` 安装，必须保持**零运行时依赖、零 devDependency、无构建步骤**。任何借鉴都不得引入 npm 依赖。

## 2. 目标

把「可复用、可验证、可追溯」三件事做成插件仓库的常规，而不是每次靠对话记忆。

## 3. 范围（做）

### 3.1 DSH API 核实记录（新增文档）

新增 `docs/design/DSH-API-核实记录.md`，格式抄 DSH-Bot 的 `docs/dsh-api-notes.md`：每条 = 结论 / 证据（源文件:行号 或 实测日志）/ 反例或坑。

首版收录本轮已实证的条目：

1. 模块级 `export const inject` 声明的服务，才可直接 `ctx.get()`；声明外的服务（`uiWorkspace`、`layout`）必须走 `ctx.inject(names, cb)`。反例：0.3.3 日志 `panel:watch:unavailable` + `jump:noWorkspace`。
2. `main` 面板必须先于同名 `sidebar.panellist` 行注册，否则宿主按 `layout.selectPanel` 抛「main panel "X" is not registered」。
3. 行图标是工厂插槽 `sidebar.panel.icon`，注册第二参为 React 组件，收到 `{ size, active }`；宽栏 16px / 窄栏 18px。
4. `uiWorkspace.openSession(id)` 内部会 `selectPanel(null)`，不需要额外收面板；失败时回退提示文案。
5. `label` 必须是函数才会随状态刷新，字符串在注册时固化。
6. DS Bot 的界面切换是 `localStorage['ds-bot:surface']`（`bot` | `agent`）+ `shadow()` 替换，不碰 `sidebar.panellist`；bot 模式会收窄整列、隐藏 DSH 原生全局行。
7. 实测环境：DSH 0.2.2-rc.3 desktop、Windows；证据日志路径 `~/.dsh/logs/dsh-bot-team-tab.log`。

### 3.2 测试迁移到 Node 内置 test runner（不引依赖）

- 删除 `scripts/selftest.mjs`，新建 `test/`：`normalize.test.mjs`、`unwrap.test.mjs`、`glyph.test.mjs`、`registration.test.mjs`、`navigation.test.mjs`。
- 用 `node:test` + `node:assert/strict`，复用现有「stub `window.__ModuleLoader__` + stub `require('react')`」加载 `lib/client.js` 的方式。
- 断言从 16 条扩到 ≥ 28 条，新增覆盖：`avatars:'ref'` 缺失时的回退、`shape` 非法值回退、行 drop 后重注册、面板订阅在 scope 变化后重挂、`openSession` 抛错时的提示文案。
- `node --test test/` 必须可直接跑通，退出码 0。

### 3.3 check 链（package.json scripts）

```json
"check": "node --check lib/client.js && node --test test/ && node scripts/check-docs.mjs"
```

`scripts/check-docs.mjs`：扫描仓库内 `.md` 的相对链接与反引号内路径，目标不存在即失败（零依赖实现，约 40 行）。

### 3.4 发布文档与 CHANGELOG

- 新增 `CHANGELOG.md`，倒填 0.3.1 / 0.3.2 / 0.3.3 / 0.3.4 / 0.4.0 / 0.4.1 六段，每段一句话写「交付了什么 / 已知限制」。
- 新增 `docs/releases/<version>.md`，模板四段：**产物与 SHA-256 / 本版验收范围 / 已知限制 / 回退方式**。首版为 `docs/releases/0.4.2.md`。
- `docs/验收.md` 保留为真机验收清单，开头加一行指向对应 release 文档。

## 4. 不做

- 不引入 vitest / biome / pnpm workspace / monorepo：与「零依赖即装即用」冲突。
- 不做 TLA+ 形式化规格与 evals 评测框架：插件无协议状态机、无模型调用，收益为零。
- 不迁移到 Typert RPC：本插件只有一条宿主日志路由，`connection.fetch.register` 已足够。
- 不改任何 UI 行为：本版不动行、图标、点击链路、BOT 胶囊。

## 6. 验收标准

1. `npm run check` 三关全绿（语法 / 测试 ≥28 条 / 文档链接）。
2. `node --test test/` 单独执行退出码 0，无 skip。
3. `git status` 干净，tag `v0.4.2` 已 push，`codeload` 匿名可取。
4. 装机后 `~/.dsh/logs/dsh-bot-team-tab.log` 出现 `v: "0.4.2"`，左栏玄机 / 安澜两行仍在，点击仍进会话，图标仍按 shape 绘制。
5. 安装体积不变：`files` 字段不新增 `test/`、`scripts/`（测试只在仓库内跑）。

## 7. 发布与回退

- 发布：`dsh plugin --profile desktop add github:mufeng-git/dsh-bot-team-tab#v0.4.2`（写 profile 需 danger-full-access），装完 DSH 自行热加载。
- 回退：`add ...#v0.4.1`；本版不改 UI，回退无数据迁移。

## 8. 风险

- 唯一实质风险是把测试从 `scripts/` 挪到 `test/` 时，加载 `lib/client.js` 的桩代码需要重写一遍（现有 stub 可直接搬，预计 30 分钟）。
- `check-docs.mjs` 若正则过宽会误报反引号里的命令片段；做法是只检查含 `/` 或以 `.md` 结尾的反引号片段。
