# 团队面板 · 规格书 v1

- 日期：2026-11-15
- 对应需求：把 DS Bot 的团队视图能力搬进 **agent 模式**（DSH 原生界面），不接管整列、不 shadow 宿主插槽
- 状态：待确认（确认后实现 0.5.0）

## 1. 背景与目标

DS Bot（Fei2411/DS-Bot）用 `shadow()` 以 `BOT_PRIORITY = -100` 替换 `sidebar.workspaces`、`conversation.chat.node` 等宿主插槽，在 bot 模式下把整列换成自己的 TeamSidebar；代价是 DSH 原生全局行（插件 / 自动化任务 / 待办 / 搜索）全部不可用。

目标：在 **agent 模式**下用 DSH 原生插槽提供同一份团队视图——名册、状态、最近消息、未答问题、审批提醒、房间与 DSH Agent——点击仍然进入**原生会话界面**。这样「界面不统一」的取舍消失：原生 UI 保留，团队视图另开一处。

**边界**：不 fork、不 patch、不 shadow DS Bot；只读它同源的 `POST api/bot`。DS Bot 不装或未启动时，插件退化为当前的每 Bot 一行（0.4.x 行为），不报错。

## 2. 范围

### 做（V1）

1. **团队面板**：左栏一行「团队」（`sidebar.panellist`，order `-2`，即排在 Bot 行之上），选中后主区域渲染总览面板。
2. **分组卡片**：按 `sections` 分组；每组内依次是 Bot 卡、房间（群聊）卡、DSH Agent 卡。卡片显示：线性字形图标、名称、角色、状态、最后一条消息预览与相对时间。
3. **状态汇总条**：面板顶部一行「N 在跑 · M 等你 · K 条审批」，点击汇总条跳到对应卡片。
4. **点击即进入**：点卡片 = `uiWorkspace.openSession(sessionId)`，随后 `layout.selectPanel(null)`；与 0.4.x 的 Bot 行行为一致。
5. **会话内标识**：`conversation.session.header.actions` 注入一个只读 `BOT` 胶囊，仅当该会话属于某个 Bot / 房间时出现。
6. **增量轮询**：`POST api/bot` 的 `state` 支持 `{since: revision, live: liveKey}`，命中则只回 `{unchanged:true, liveKey}`；V1 采用该机制，空闲时不再拉整包。
7. **保留现有每 Bot 一行**（0.4.x）；团队面板是总览，不是替代。

### 不做（V1）

- 写操作：发消息、答审批（`approval-answer`）、停止任务、改 Bot（`update-bot`）、建房间——一律留给 DS Bot 自己的界面。V2 再议。
- 不碰 `sidebar.workspaces`：该插槽是 `kind:'single'` 且已被 `dsh-client-ui-workspace` 占用（`dsh-client-ui-workspace/src/client/index.ts:369`），注册即替换，会砸掉原生会话列表。
- 不复制 DS Bot 的 145 个端点；V1 只用 `state`（必要时 `avatar` 取图）。
- 不做真实头像图片：仍是按 `avatar.shape` 画的单色线性字形（0.4.1 已定）。

## 3. 数据契约（已核实）

请求：`POST api/bot`，body `{ endpoint: 'state', payload: { since?, live?, models?, locale? } }`；响应 `{ ok: true, value }` / `{ ok: false, error: { code, message } }`。

`value` 里 V1 用到的字段（`ds-bot/src/host/channel.js:62-149`）：

| 字段 | 含义 |
| --- | --- |
| `revision` | 状态版本号；`since` 与它相等即命中未变 |
| `bots[]` | `{ id, name, role, color, avatar.shape, sessionId, parts[], waiting?, blocked?, lastAt?, preview?, engine? }` |
| `rooms[]` | `{ id, name, sessionId, ownParts[], parts[], lastAt?, preview? }` |
| `agents[]` | 团队里的 DSH Agent（原生 Session，不是 Bot） |
| `sections[]` | 按工作流分组的容器 |
| `mainBotIds[]` | 主 Bot 列表，`mainBotId` 为首个 |
| `questions` | 待答问题 |
| `work` | `{ bots, rooms, approvals, waiting, turns }`——运行中回合、等待交接、待批事项 |

> 第 0 步（实现时先做）：连本机 DS Bot dump 一次 `state` 原始 JSON，把 `work.bots` / `work.approvals` / `work.waiting` / `questions` 的真实结构记进本文档，再写渲染。

**六态判定**（沿用 0.2.1 的词典，字段映射在第 0 步后锁定）：

| 态 | 判据 | 文案 |
| --- | --- | --- |
| needs-you | `work.waiting[botId]` 或 `questions` 有该 Bot | 等你 |
| working | `work.bots[botId]` 有运行中回合 | 在跑 |
| waiting-bot | 交接给其它 Bot | 等队友 |
| failed | `bots[].blocked` | 需要你处理 |
| just-finished | `lastAt` 在 10 分钟内且无运行回合 | 刚完成 |
| idle | 其余 | 空闲 |

## 4. 插槽与接线

| 位置 | 插槽 | 说明 |
| --- | --- | --- |
| 左栏行 | `sidebar.panellist` | `{ name, id: 'zdhcs:team', order: -2, label: () => t('团队') }`，第二参为图标组件 |
| 面板正文 | `main`（key 同上） | **必须先注册**，否则宿主拒绝选中（见 DSH-API-核实记录第 2 条） |
| 会话头 | `conversation.session.header.actions` | `kind:'list'`、`scope:'session'`，只读胶囊 |
| 服务 | `ctx.inject(['uiWorkspace','layout','slots'], …)` | 见 DSH-API-核实记录第 1 条 |

行名与汇总数字用函数式 `label`/渲染从 store 实时取值，不用注册时快照。

## 5. 交互细节

- 卡片整块可点，键盘 Tab 可达（`role="button"`），Enter/Space 触发。
- 面板滚动区独立；顶部汇总条固定在面板内顶部（`position: sticky`）。
- 点卡片后立即 `selectPanel(null)`，不等待 `openSession` 返回；失败写日志并显示一行提示。
- 空态：DS Bot 未运行 → 「没连上 DS Bot」+ 重试按钮；名册为空 → 「还没有队友」。
- 深链不变：仍然只打开会话，不引入路由。

## 6. 验收标准

自动化（`npm run check`）：

1. 分组投影：输入混排的 bots / rooms / agents / sections，输出各组顺序正确、无 section 的条目落「未分组」。
2. 六态判定：六个分支各自的输入都映射到预期态与文案。
3. 增量轮询：`since` 命中 → 不发第二个整包请求；`live` 变化 → 只更新运行态，不重建行。
4. 点卡片：`selectPanel(null)` 先于 `openSession`，且 sessionId 正确。
5. 会话归属：命中 Bot 会话渲染胶囊，未命中返回 `null`。
6. 退避：连续失败按 `[5000, 10000, 20000, 30000]`，恢复后回到 5 秒。

真机：

1. 左栏「团队」行在「玄机」之上，图标与其它导航图标同风格。
2. 点「团队」→ 主区域出现分组面板，玄机 / 安澜 / 房间 / DSH Agent 各就位。
3. 点玄机卡 → 进入玄机会话，面板退出，头部有 `BOT` 胶囊。
4. 让某个 Bot 跑起来 → 汇总条与卡片在 ≤6 秒内变「在跑」，结束后变「刚完成」。
5. DS Bot 停掉 → 面板显示「没连上 DS Bot」，左栏 Bot 行消失，其余插件不受影响。
6. 空闲 1 分钟观察日志：`state` 请求多为 `unchanged`，不再每次拉整包。

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| `state` 回包含 connectors / secrets 元数据等大字段，首包可达数百 KB | 用增量轮询；只在 revision 变化时整包解析，解析后立刻丢弃原始 JSON |
| DS Bot 字段漂移（它 12 天 5 个 release） | 所有字段读取走 `pick()` 容错，缺字段降级而不是抛错；测试用固定夹具，不依赖线上 |
| bot 模式下重复入口 | 读 `localStorage['ds-bot:surface']`，为 `bot` 时不注册「团队」行（bot 模式里 DS Bot 自己的 TeamSidebar 已在） |
| 面板插件与 DS Bot 抢同一个 `main` key | key 用 `zdhcs:team`，与 DS Bot 无交集（它的面板 id 形如 `bot`、`ds-bot:…`） |
